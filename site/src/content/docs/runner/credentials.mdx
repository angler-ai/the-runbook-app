Open **Settings › Organization › Runner › Credentials** and choose **Add credential**. Select the type, enter the destination settings, and decide which projects can use it. Sharing starts at **none**.

| Type | Secret field | Destination and delivery |
| --- | --- | --- |
| `api-key` | `key` | The gateway adds a header to requests to the declared hosts. |
| `model-provider` | `api_key` | The gateway adds the key to requests to the bound provider and endpoint. |
| `mcp-bearer` | `token` | The gateway adds the bearer token to requests to the bound MCP server URL. |

New model provider keys default to `read`. New API keys and MCP bearer
tokens default to `destructive`. Review the label against the upstream
permissions before binding a credential to an agent. Existing labels carry
over when you upgrade.

Check the destination shown in the form before you enter the secret.
The browser verifies the ingest key against the registered vault identity,
then seals the secret to that key. The core and runner API relay the sealed value. The vault checks the binding and version before storing it, and returns metadata such as a fingerprint. Use **Test connection** to check the binding. If the test fails, the result gives an error class such as unauthorized or unreachable.

## Enter a secret with the CLI

Check the [vault identity](/runner/setup/#verify-the-vault-identity) before sealing the first secret. Run `runbook runner credential types --json` to see the supported types, config fields and secret field names. Create metadata from a local JSON file containing `name`, `type`, `config` and `groups`. Add the desired `label` and `sharing` when creating it. For example, use `{"projects":["PROJECT_ID"]}` for sharing and set `groups` to the allowed group IDs or `"all"`. Keep the secret in a separate protected file or enter it at the prompt.

For example, save model-provider metadata as `credential.json` and substitute the allowed group and project IDs.

```json
{
  "name": "Primary model key",
  "type": "model-provider",
  "config": {"provider": "anthropic", "endpoint": "https://api.anthropic.com"},
  "groups": ["GROUP_ID"],
  "label": "read",
  "sharing": {"projects": ["PROJECT_ID"]}
}
```

```sh
runbook runner credential create --file credential.json --json
runbook runner credential set "$CREDENTIAL_ID" "$FIELD"
runbook runner credential test "$CREDENTIAL_ID"
```

Use the returned credential ID and the field name from the table. The CLI verifies the ingest key against the registered vault identity and displays the normalized destination for confirmation before reading the value from a hidden prompt. An independent ingest-key fingerprint can be supplied with `--pin`. The ingest key rotates and has a different fingerprint from the vault identity.

For standard input, supply a local file containing the expected `type`, `config` and `groups`, or pin the independently verified destination `binding_hash` from credential creation. The CLI checks the destination before reading the value.

```sh
runbook runner credential set "$CREDENTIAL_ID" "$FIELD" \
  --expected-config credential.json < "$SECRET_FILE"
# Or provide a verified destination hash.
runbook runner credential set "$CREDENTIAL_ID" "$FIELD" \
  --binding-pin "$BINDING_HASH" < "$SECRET_FILE"
```

Use `runbook runner credential label "$CREDENTIAL_ID" read` to change the label after reviewing the upstream permissions. Use `runbook runner credential share "$CREDENTIAL_ID" --file sharing.json` with `{"sharing":{"projects":["PROJECT_ID"]}}` to replace the full project-sharing list. If a change returns a `proposal_id`, have the appropriate administrator approve the proposal before using the new access.

MCP servers and hosts that agents reach through the gateway must be public `https` addresses on port 443. The gateway refuses private, loopback and link-local addresses.

Use a different credential for each set of permissions and destinations. Where possible, use read-only credentials and scope them to the smallest set of resources the agent needs. Sharing a credential makes it available for a project admin to bind to agents. A project editor can steer an agent that already has the binding.

Use **Replace** in the credential form to rotate a value. Changing the destination binding requires a fresh seal for that binding. **Revoke** stops the runner from issuing releases and invalidates active releases. Rotate the value at the provider if you suspect exposure.
**Delete** removes the credential from the catalog and destroys its stored
key material in the live vault. Backups with the old wrapped keys retain it
until they expire.

See [security boundaries](/runner/security/#entering-secrets) for the scope of browser sealing.
