## One run, start to finish

The graph above is this runbook. An agent claimed both checks through the
CLI and reported what it found. A person on call made the decision, because
agents can never cast an approval. Roll back would have run only if they
had chosen it. The run keeps all of it as a record you can read, search and
export.

<div class="rb-pair">

```yaml title="post-deploy.yaml"
metadata: { id: post-deploy }
spec:
  inputs:
    service: { type: string, required: true }
  steps:
    - id: verify
      parallel:
        - id: check_health
          actor: agent
          check: true
          instructions: Pass if /healthz returns 200 within 500 ms.
        - id: compare_error_rate
          actor: agent
          check: true
          instructions: Compare the 5xx rate with the last hour.
    - id: decide
      approval:
        prompt: Keep ${{ inputs.service }} at this version?
        options: [keep, rollback]
        approvers: { teams: [oncall] }
    - id: roll_back
      if: "${{ steps.decide.outputs.decision == 'rollback' }}"
      actor: agent
      destructive: true
      instructions: Roll back to the previous release.
```

## What it is

The Runbook is a system of record for operational work, such as
post-deploy checks, incident triage, migrations and releases, whether an AI
agent or a person does each step. You write the procedure once; each time
it runs, the server tracks every step to completion and keeps who did it,
what they reported and the evidence they attached.

<CardGrid>
  <Card title="One file per procedure" icon="document">
    Steps, inputs, approvals, loops and parallel branches in a short YAML
    file you keep in git. The server checks it before anything runs.
  </Card>
  <Card title="Agents do the toil" icon="rocket">
    Claude Code, Codex, Cursor or your own agent claim steps under a lease,
    report outputs and attach evidence, through the CLI or MCP.
  </Card>
  <Card title="People keep the judgment" icon="approve-check">
    Approvals by named people, destructive steps that need a human,
    take-overs, reminders and escalation. Agents never cast human approvals.
  </Card>
  <Card title="A record you can read" icon="open-book">
    Every run reads like a document: who did each step, their outputs, logs
    and evidence. Export it as Markdown, JSON, JUnit or PDF.
  </Card>
</CardGrid>
