An **approval** asks named approvers to choose between options. Later steps
read the choice as `steps.<id>.outputs.decision`, with the approver's
`comment` and who `decided_by`.

```yaml title="ship-or-hold.yaml"
metadata: { id: ship-or-hold, owners: [team:release-managers] }
spec:
  inputs:
    version: { type: string, required: true }
  steps:
    - id: go_no_go
      approval:
        prompt: Ship ${{ inputs.version }} to every region?
        options:
          - { id: ship, title: Ship it }
          - { id: hold, title: Hold the release }
        approves: [ship]
        approvers: { teams: [release-managers] }
        timeout: 2h
        escalate_to: [team:eng-leads]
    - id: rollout
      if: "${{ steps.go_no_go.outputs.decision == 'ship' }}"
      actor: agent
      destructive: true
      instructions: Roll out ${{ inputs.version }} everywhere.
```

## Who decides

- `approvers` names `users` and `teams`; they resolve when you publish, and
  publishing requires at least one (`spec.approvers_required`).
- `min` (default 1) is how many approvers must choose the same option. Each
  person votes once.
- People decide in the web app, from their inbox, from
  [Slack](/operating/slack/) or with the CLI:

```sh
runbook me tasks --kind approval          # what's waiting on me
runbook step decide "$SR" --option ship --comment "Canaries are clean"
```

## Timeouts and escalation

<Flow
  steps={[
    { title: 'Requested', text: 'approval.requested to the approvers', tone: 'human' },
    { title: 'Escalated', text: 'At timeout: to escalate_to (or the owners)', tone: 'human' },
    { title: 'Expired', text: 'At escalation_timeout, undecided', tone: 'muted' },
    { title: 'Paused or failed', text: 'By on_expired', tone: 'system' },
  ]}
/>

- `timeout` starts the clock. At it, `on_timeout: escalate` (the default)
  hands the approval to `escalate_to`, or to the runbook's `owners`; the
  original approvers can still decide.
- `escalation_timeout` (default: the same as `timeout`) is how long the
  escalated approval waits. Undecided by then, it **expires**, and
  `on_expired` either pauses the run for a person (`pause`, the default) or
  fails the step (`fail`).
- `on_timeout: { decide: <option> }` instead decides automatically at the
  timeout. The option must be marked `auto: true`.

## Destructive runner steps

A destructive step that targets a named runner agent needs a human decision
from an approval it encounters on every path. Set `approves` to the option
IDs that grant permission.

```yaml
approval:
  prompt: Proceed with the deployment?
  options: [ship, hold]
  approves: [ship]
  approvers:
    teams: [on-call]
```

A person choosing `hold` completes the approval without unlocking the
destructive step. Use a step condition to skip the rollout when a person
chooses to hold, as in the first example.

New publications need `approves` unless the task's `if` already requires
the approval's decision to equal a specific option
(`spec.destructive_approval_options`). An existing published version with
neither keeps its original behavior: any human decision on the gate can
unlock the task. Put the approval inside a loop if each iteration needs
its own sign-off. A gate outside it covers the whole loop and publishing
warns about it.

## Agents and approvals

`allow_agents: true` permits an agent to decide an approval with `min: 1`.
Agent decisions are recorded separately from human signatures. A decision
by an agent never counts toward a human quorum.

### A runner agent decides

Add `agent` to an `allow_agents` approval to have one of the project's
[runner agents](/runner/agents/) decide it when no person has:

```yaml title="release-gate.yaml"
metadata: { id: release-gate, owners: [team:release-managers] }
spec:
  inputs:
    version: { type: string, required: true }
  steps:
    - id: canary
      actor: agent
      title: Measure the canary
      agent: { name: canary-checker }
      outputs:
        error_rate: { type: number, required: true }
    - id: release_gate
      approval:
        prompt: Ship ${{ inputs.version }}? Canary error rate is ${{ steps.canary.outputs.error_rate }}.
        options:
          - { id: ship, title: Ship it }
          - { id: hold, title: Hold the release }
        approvers: { teams: [release-managers] }   # still required; people can always decide
        allow_agents: true
        agent: { name: release-reviewer, after: 15m }  # decides if no person has after 15m
        timeout: 2h
```

- **People first.** `agent.after` is how long the approval waits for a
  person before the agent starts. Without it, the agent starts as soon as
  the approval opens. Either way people can decide at any time, and the
  first decision wins: when a person decides while the agent is reviewing,
  the runner's decision lease is revoked and a late answer is refused
  (`approval.not_open`). A manual pause also revokes the runner lease.
  The configured delay applies to external agents as well.
- **Read-only.** A decision run gets the built-in Runbook tools (this run,
  earlier runs and memory) and only the agent's tools, credentials and
  hosts labeled `read`, with no sandbox or memory proposals. Review the
  labels on the upstream tools and credentials you share with the agent.
- **One of the listed options.** The agent must pick an option from the
  approval and cite the tool calls its reason rests on (`[call N]`). If the
  evidence doesn't support an option, it abstains: its reason shows on the
  approval and people decide.
- **Never before a destructive step.** Publishing still refuses an
  agent-decidable approval that can lead to a destructive task
  (`spec.agent_approval_destructive`).
- **Timeouts still apply.** If neither a person nor the agent has decided
  by `timeout`, `on_timeout` escalates or decides as usual.
- `agent` without `allow_agents: true` is a publish error
  (`spec.agent_requires_allow_agents`). `agent.name` must name an agent in
  the project (`spec.agent_unknown`); `agent.model`, `agent.max_cost_usd`
  and `agent.max_tokens` must be within what the agent allows
  (`spec.agent_outside_ceiling`). See the
  [key reference](/reference/keys/#specstepsapprovalagent).

While the approval is open, its card on the run page says when the agent
may decide, then "agent `release-reviewer` is reviewing" while it works;
the inbox marks the approval the same way. Once it decides, the card shows
"decided by agent `release-reviewer` (model)" with its reason, the evidence
it cited and a link to the runner transcript. Citations are runner-reported
references to tool calls. Review the transcript to check the evidence.
An abstention shows as "agent `release-reviewer` abstained" with the reason. `runbook run get` and
`runbook run report` show the same, and the agent's page lists its recent
decisions.

## Destructive steps

`destructive: true` marks a step that changes something you can't easily
undo, such as a rollback, deletion or failover. The publication rules
apply to destructive tasks generally. A named runner agent additionally
needs the human gate described above.

| A decision made by | May lead to a destructive step? |
| --- | --- |
| A person | Yes |
| An agent (`allow_agents`, including a runner agent) | Never (`spec.agent_approval_destructive`) |
| A timeout (`on_timeout: decide`) | For tasks outside the runner, only with `allow_auto_decision: true` (`spec.auto_decision_destructive`) |

```yaml title="auto-rollback.yaml"
metadata: { id: auto-rollback }
spec:
  steps:
    - id: keep_or_roll_back
      approval:
        prompt: The error rate doubled after the deploy. Roll back?
        options: [keep, { id: roll_back, auto: true }]
        approvers: { teams: [oncall] }
        timeout: 15m
        on_timeout: { decide: roll_back }
    - id: roll_back
      if: "${{ steps.keep_or_roll_back.outputs.decision == 'roll_back' }}"
      actor: agent
      destructive: true
      allow_auto_decision: true
      instructions: Roll back to the previous release.
```

<Aside type="note">
These rules are checked when you **publish**, not by offline
`runbook spec validate`. The server also checks them again when an
automatic decision is about to be made.
</Aside>
